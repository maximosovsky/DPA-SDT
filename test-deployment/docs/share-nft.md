# Separate participant-share NFT (local prototype)

`DPAFormation` is the agreement record, **not an NFT**. Deploy one `DPAShareNFT(formationAddress)` for an already deployed formation. Constructor checks code and the expected formation getter surface plus participant/share invariants; it does **not** authenticate canonical formation bytecode. The frontend/integrator must independently verify formation code and immutable constructor state before allowing any wallet signing or claim. No public deployment or publication is included here.

## Contract/API handoff

Current `DPAFormation` getter interface consumed: `participants() returns (address[])`, `shares() returns (uint8[])` (whole percentages, positive, total 100), `complete() returns (bool)`, `acceptances(address) returns (uint256 tokenId, bytes32 identityHash, uint256 blockNumber, bool accepted)`, `agreementHash() returns (bytes32)`, `versionHash() returns (bytes32)`. This pins the actual concurrent contract's whole-percent design: `shareBps = uint256(shares[index]) * 100`; it does not invent fractional shares.

`DPAShareNFT.formation() -> address`, `chainId() -> uint256` (deployment snapshot), `claim() -> uint256`, `tokenOf(address) -> uint256` (zero means unclaimed; ID = one-based index in formation participants), `totalClaimed() -> uint256`, standard `ownerOf`, `tokenURI`, `locked`, `supportsInterface(0xb45a3c0e)`. `claim()` only mints to `msg.sender` after `complete()` and their own recorded acceptance. No recipient override, burn, transfer, approval, sale, payout, governance, or permission for token ownership to assign contractual rights. ERC-721 and ERC-5192 advertise ownership and lock status. A new formation/version requires a separate new NFT contract; existing tokens keep their original agreed share.

`tokenURI` is `data:application/json;base64,...` with nested `data:image/svg+xml;base64,...`. Both use only fixed literals, hex addresses/hashes and decimal share/chain ID: no agreement/version text, identity digest, personally identifying fields, or raw arbitrary SVG/JSON input. Contains wallet, formation, deployment chain, agreement/version hashes, exact share basis points and percent. Version is represented by its hash, not its potentially malicious raw text. A later burn of an SDT does not erase the frozen formation acceptance.

Client export `shareNftAbi` plus `verifyShareNftCode(code,nftAddress,formationAddress,chainId)` and `preflightShareNft(publicClient,nftAddress,formationAddress,chainId)` in `src/share-nft.ts`. Call preflight **before enabling** contract-dependent controls and again immediately before signing/claiming; it compares exact artifact runtime with both compiler immutable substitutions, readback getters, network and presence of formation code. It does not replace an independent formation bytecode/immutables check or participant acceptance checks; wallet account changes require fresh reads. Artifact output must be generated by the pinned Hardhat compiler settings before bundling; fail closed on compiler immutable layout changes. Avoid hardcoding artifact hashes across a new compile.

Local tests: `npx hardhat test test/DPAShareNFT.test.ts`; whole repository: `npm test`; frontend: `npm run build`. This is an experimental evidence token, not a tradable security or a legal determination of rights.
