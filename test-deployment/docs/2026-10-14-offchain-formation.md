# 2026-10-14 — Off-chain DPA formation document (unpublished candidate)

## Decision

The new `DPAFormation` constructor takes `(sdt, agreementHash, version, documentRef, participants, shares)`. `agreementHash` is Keccak-256 of the exact UTF-8 bytes of the agreement **text string**, not the JSON package. The existing EIP-712 acceptance message retains its `agreementHash`, `versionHash`, ordered `participantsHash`, SDT, token, identity hash and nonce. The formation is a non-NFT agreement record. Historical on-chain contracts remain immutable; earlier pilot evidence was removed from this repository’s current tree at the owner’s request. The original article is unchanged.

The author freezes a synthetic draft, downloads `dpa-evidence.json`, deploys only the hash/short reference and shares that file with each participant outside the chain. The package has `format`, full `text`, `version`, ordered `people`, `shares`, and independently recomputable hashes. A recipient follows the address/chain invitation, verifies canonical formation bytecode and getters, imports the file, checks exact UTF-8 text hash plus version and ordered allocation, reads the text, and only then can sign. Replacing a verified file with invalid evidence disables signing. Reloads, wallet changes and record changes clear verification. No agreement text is put in deployment calldata, contract storage, logs or token metadata by this application. Participants and share allocation remain public. The agreement hash is not encryption or secrecy: anyone possessing the file can read it, and low-entropy text may be guessable.

`documentRef` is optional: empty, a short HTTPS URL without credentials/query/fragment, or `ipfs://CID`. HTTPS retrieval is direct from the browser with omitted credentials and no referrer; CORS and availability must be provided independently. The browser does not automatically resolve IPFS CIDs through a third-party gateway; download the file from the author instead. Neither a CID nor a URL pins, pays for, backs up, or guarantees delivery of the document. The invitation URL contains only contract address and chain. No backend fetch, paid storage, public network transaction or release is performed by this change.

**Operational boundary:** author must retain and distribute the package; each signer needs the exact package or a functioning CORS-enabled HTTPS source. If absent, altered, or inaccessible, signing fails closed. The application cannot reconstruct the full agreement from the on-chain hash. Synthetic experiments only; no assertion of legal enforceability or identity verification.
